Generate a configuration

Open Generate. Workflows are listed above the templates. Open a workflow for the procedure and the templates it uses. Open a template to fill in the form. The rendered IOS-XE text is shown so you can copy it into the switch CLI. The server does not save that text.

View raw template, under the template name, shows the locked template text. It is not filled in. Download .txt on that page saves the same text, including each paste block and the follow-up commands. That file is not the Workshop backup.

Some templates start with instructions. Read them before filling in the fields. After the configuration is generated, the same instructions stay above the paste. They are not part of the configuration or the downloaded file.

A dropdown starts on Choose One. Pick a listed value. The configuration is not generated while that prompt is still selected.

Some templates split the configuration into paste blocks. Paste the main configuration, then each block in order. Each block is its own copy. Each copy box can have a title and a short note. The note is shown above that paste and left out of the download. A blank main title is shown as Configuration. A blank note adds nothing.

A paste can be marked Console, SSH, or Pause. The word appears beside that heading, and the paste changes color. The mark is left out of the paste and the downloaded file.

Follow-up commands, when the template has any, appear in their own box after the pastes. They use the same fields. A blank follow-up is omitted, and the downloaded file leaves it out. A blank follow-up title is shown as Run these separately.

Generated configurations contain passwords and keys. Keep this site on the engineering network.

Workshop

Editors and approvers use Workshop to change the standards. Operators do not.

  • New template starts a draft. It stays off the generate page until an approver locks it.
  • New workflow starts a draft page. Attach the locked templates it uses, write the page, and submit it. Operators see a locked workflow above the templates. Revise leaves the locked page in place.
  • Revise on a locked template opens a new draft and leaves the locked copy in place. Engineers keep generating from the locked copy while the draft is in progress.
  • Duplicate on a locked template opens a new draft with the same fields and commands. The locked template stays as it is. Give the copy its own name before you submit it.
  • Save a draft, preview it, then submit it. A submitted revision waits under Waiting for approval.
  • Cancel deletes the draft. Nothing is sent for review. A locked template stays as it is.
  • Download backup saves the locked and retired templates. Import backup puts that file back. An approver does both from Workshop. Drafts are not in the file.
  • An interface range field is a Cisco range such as GigabitEthernet1/0/1 - 48. Up to five ranges can be separated by commas.
  • Move up and Move down change the order of fields in a section, and the order of the sections. The generate form follows that order.
  • A choices field is a checkbox list, up to 40 rows, written as value | label. Nothing starts checked. The template loops over the checked rows.

Template syntax

The main configuration, each paste block, and the follow-up commands can use the fields on the form. A name that is not a field is refused. Templates cannot include other files.

Write a field in double braces:

hostname {{ '{{ hostname }}' }}

An empty optional field is blank, so this skips the line when NTP server 1 is empty:

{% raw %}{% if ntp_server_1 %}
ntp server {{ ntp_server_1 }}
{% endif %}{% endraw %}

Chain other cases with {% raw %}{% elif %}{% endraw %} and {% raw %}{% else %}{% endraw %}. Close the block with {% raw %}{% endif %}{% endraw %}. The same test can sit inside one line. Several fields can be combined with or:

{% raw %}{% if timezone == "UTC" %}
clock timezone UTC 0 0
{% elif timezone == "Eastern" %}
clock timezone EST -5 0
{% else %}
clock timezone PST -8 0
{% endif %}
aaa group server tacacs+ {% if mgmt_path == "oob" %}MGMT-TACACS{% else %}TACACS{% endif %}
{% if tacacs_server_1 or tacacs_server_2 %}
aaa new-model
{% endif %}{% endraw %}

A yes/no field is the text yes or no. Both are filled in, so compare it with yes:

{% raw %}{% if snmp_enabled == "yes" %}
snmp-server community {{ snmp_community }} RO
{% endif %}{% endraw %}

A choices field is a list. The engineer checks any number of rows, and nothing starts checked. The template loops over the checked rows in the order they are written. Each row has value and label. At most 40 rows.

{% raw %}{% for vlan in user_vlans %}
vlan {{ vlan.value }}
 name {{ vlan.label }}
{% endfor %}
{% if user_vlans %}
interface {{ uplink_interface }}
 switchport trunk allowed vlan {{ mgmt_vlan }}{% for vlan in user_vlans %},{{ vlan.value }}{% endfor %}
{% endif %}{% endraw %}

A choices field can be shown, or made required, from another field. Another field cannot be shown or made required from which rows are checked. Required when any listed field is filled can see that the list is not empty.

A loop can also split a multiline field into lines:

{% raw %}{% for line in banner_text.splitlines() %}
{{ line }}
{% endfor %}{% endraw %}

A comment is left out of the paste:

{% raw %}{# Kept for the next editor. Not pasted. #}{% endraw %}

A run of blank lines in the result becomes one blank line.

Approval

An approver opens Review on a submitted revision and compares it with the locked template.

  • Approve and lock puts that revision on the generate page. The previous locked revision is kept in the history.
  • Send back returns it to the editor with a note.
  • Reject closes the revision so it is never locked. A short reason is required. A template already on the generate page stays there. The reason remains on the Rejected list and in the template history.

Retire and roll back

Retire takes a locked template off the generate page. Restore puts it back. Retire does not delete the template or its history. Workflows work the same way.

An admin can Delete a retired template or workflow, or a rejected revision, when nothing else is attached. A draft, a revision waiting for approval, someone editing it, or a workflow that still lists the template keeps it in place, and the workshop says why. The confirmation page says the delete cannot be recovered. A rejected change to a template or workflow that is still locked or retired stays in the list.

Roll back on the history page locks an older revision again. The revision that was locked becomes an archived revision.

The sample template is added when the app starts and the database has no templates.

Accounts

The app holds at most 10 accounts. An admin adds accounts, resets passwords, removes accounts, and assigns roles from Users. At least one admin has to remain.

Any signed-in user can change their own password from Password.

  • Operator — generate configuration from locked templates.
  • Editor — also create drafts, preview them, and submit them.
  • Approver — also lock a draft, send it back, reject it, retire, restore, and roll back.
  • Admin — also manage the accounts, the stored keys, and permanent deletion of retired or rejected templates and workflows that have nothing else attached.

Stored keys

An admin stores shared secrets on the Secrets page. Each one has a name and a field name. A new database starts with four unset names that match the sample template: local_secret, enable_secret, config_key, and tacacs_key. Add, rename, or remove names for the templates you use. The page holds at most 8. The values are not written into the template.

On the generate form, a password field whose name matches a stored secret shows Stored key in gray while it is empty and the secret has a value. Leave it blank to use the stored value. Type a different value to use that for this switch only. The typed value is not saved.
